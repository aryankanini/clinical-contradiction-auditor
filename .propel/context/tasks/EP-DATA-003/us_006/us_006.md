# User Story - US_006

## Story ID

- ID: US_006

## Story Title

- Emit rule-ready missing relationship signals

## Status

- **State**: Closed
- **Superseded By**: N/A
- **Change Request**: N/A

## Description

- As a rule governance engineer, I want ingestion outputs to distinguish generic incompleteness from rule-expected missing relationships, so that downstream rules can flag only governed relationship gaps.

## Business Value

- Preserves the spec’s safety boundary by ensuring missing-relationship findings are governed by explicit rule expectations instead of universal clinical assumptions.

## Acceptance Criteria

### AC-01: Mark generic incompleteness separately

- **Given**: A record lacks data needed for evaluation but no rule-expected relationship definition applies
- **When**: The ingestion layer emits validation results
- **Then**: The output is marked as generic incompleteness
- **And**: No governed missing-relationship signal is produced

### AC-02: Mark rule-expected relationship gaps

- **Given**: A rule-governed relationship is expected for an evaluated record set and the required link is absent or unsupported
- **When**: The ingestion layer emits validation results
- **Then**: The output includes a rule-ready missing-relationship signal
- **And**: The signal preserves the relationship context needed by downstream rule evaluation

### AC-03: Preserve audit-only boundaries in validation output

- **Given**: A missing-relationship signal is produced
- **When**: The ingestion result is recorded
- **Then**: The output does not imply diagnostic truth or treatment action
- **And**: The signal remains explicitly tied to governed audit rules

## Edge Cases

- Relationship rules change across rule-pack versions
- A record is linked but the linked resource is unsupported for the current rule
- Multiple rule families interpret the same absent relationship differently
