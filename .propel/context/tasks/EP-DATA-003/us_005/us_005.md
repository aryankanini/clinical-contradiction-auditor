# User Story - US_005

## Story ID

- ID: US_005

## Story Title

- Validate linkage and completeness states

## Status

- **State**: Closed
- **Superseded By**: N/A
- **Change Request**: N/A

## Description

- As a data steward, I want the ingestion layer to classify missing links and incomplete records before contradiction evaluation, so that downstream rules can distinguish data-quality gaps from true contradictions.

## Business Value

- Reduces false positives and creates a cleaner operational interpretation of whether a record is incomplete, unlinked, or ready for deterministic evaluation.

## Acceptance Criteria

### AC-01: Detect unresolved cross-resource links

- **Given**: Normalized records contain references that cannot be resolved within the current ingest scope
- **When**: The linkage validation step runs
- **Then**: The affected records are marked with unresolved-link status
- **And**: The unresolved condition is available to downstream rule handling

### AC-02: Detect incomplete rule-critical fields

- **Given**: A normalized record is missing fields required for cross-resource evaluation
- **When**: The completeness validation step runs
- **Then**: The record is marked with an explicit incompleteness outcome
- **And**: The reason identifies which rule-critical field class is missing

### AC-03: Separate validation state from contradiction state

- **Given**: A record or batch has unresolved links or incomplete fields
- **When**: Validation results are emitted
- **Then**: The pipeline does not label the condition as a contradiction
- **And**: The result remains a data-ingestion or completeness signal until a downstream rule explicitly interprets it

## Edge Cases

- A record is complete by schema but unusable for one specific rule family
- A reference resolves to multiple candidate records
- One batch contains both complete and incomplete records for the same patient context
