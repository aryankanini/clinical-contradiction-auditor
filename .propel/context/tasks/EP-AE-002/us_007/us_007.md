# US-AE-007: Encounter, Procedure, Observation, CarePlan Cross-Resource Rules

## Story

As a clinical audit lead, I need to detect contradictions across Encounters, Procedures, Observations, and CarePlans so that the full patient record consistency is assured.

## User Value

These resource types represent the execution and documentation of care. Contradictions across them (e.g., encounter closed but procedures still in-progress, observations outside encounter window) indicate structural integrity problems that affect care continuity and compliance reporting.

## Acceptance Criteria

### Encounter Rules

#### Rule 1: Encounter Complete But Linked Procedures Still In-Progress
- [ ] **Trigger:** Encounter.status = "finished" OR "cancelled" AND ≥1 linked Procedure has status ≠ "completed", "cancelled"
- [ ] **Finding:** Contradiction — encounter closed but care activities incomplete
- [ ] **Evidence:** Encounter ID, status, in-progress Procedure IDs and statuses
- [ ] **Test cases:** ≥2 cases

#### Rule 2: Encounter End Date Before Start Date
- [ ] **Trigger:** Encounter.period.end < Encounter.period.start
- [ ] **Finding:** Contradiction — impossible date range
- [ ] **Evidence:** Encounter ID, start date, end date
- [ ] **Test cases:** ≥1 case

#### Rule 3: Referenced Condition Onset After Encounter End
- [ ] **Trigger:** Condition.onset_date > Encounter.period.end AND Encounter links to Condition
- [ ] **Finding:** Contradiction — condition diagnosed after encounter ended
- [ ] **Evidence:** Encounter ID, end date, Condition ID, onset date
- [ ] **Test cases:** ≥1 case

### Procedure Rules

#### Rule 1: Procedure Status Completed But Referenced Encounter Not Completed
- [ ] **Trigger:** Procedure.status = "completed" AND Encounter.status ≠ "finished", "cancelled"
- [ ] **Finding:** Contradiction — procedure marked complete but encounter still open
- [ ] **Evidence:** Procedure ID, Procedure status, Encounter ID, Encounter status
- [ ] **Test cases:** ≥2 cases

#### Rule 2: Procedure Date Outside Encounter Window
- [ ] **Trigger:** Procedure.performed_date < Encounter.start OR > Encounter.end
- [ ] **Finding:** Contradiction — procedure date outside encounter timespan
- [ ] **Evidence:** Procedure ID, procedure date, Encounter ID, encounter start/end
- [ ] **Test cases:** ≥2 cases (before, after)

#### Rule 3: Invalid Procedure Status Transition
- [ ] **Trigger:** Procedure.status transition violates clinical sequence (e.g., "not-done" after "completed")
  - Valid transitions: preparation → in-progress → completed (or stopped/not-done at any point)
- [ ] **Finding:** Contradiction — impossible procedure state sequence
- [ ] **Evidence:** Procedure ID, current status, previous status (from history if available), rule logic
- [ ] **Test cases:** ≥2 cases (clear violation, edge case)

### Observation Rules

#### Rule 1: Observation Date Outside Related Encounter Window
- [ ] **Trigger:** Observation.effective_date_time < Encounter.start OR > Encounter.end AND Observation references Encounter
- [ ] **Finding:** Contradiction — observation outside encounter timespan
- [ ] **Evidence:** Observation ID, observation date, Encounter ID, encounter start/end
- [ ] **Test cases:** ≥2 cases

#### Rule 2: Observation References Terminal Condition
- [ ] **Trigger:** Observation.related_condition has status = "resolved", "entered-in-error" AND Observation.status = "final", "amended" (active)
- [ ] **Finding:** Contradiction — active observation linked to concluded diagnosis
- [ ] **Evidence:** Observation ID, status, Condition ID, Condition status
- [ ] **Test cases:** ≥2 cases

#### Rule 3: Observation Result Contradicts Related Condition
- [ ] **Trigger:** Observation.value conflicts with Condition status/code
  - Example: Observation = "blood glucose normal" but Condition = "type 2 diabetes" (if diabetes, glucose should be abnormal in earlier observations)
- [ ] **Finding:** Contradiction — observation findings inconsistent with diagnosis
- [ ] **Evidence:** Observation ID, value, Condition ID, code, expected relationship
- [ ] **Test cases:** ≥2 cases (clear contradiction, edge case)

### CarePlan Rules

#### Rule 1: Active CarePlan With No Referenced Conditions
- [ ] **Trigger:** CarePlan.status = "active" AND (no linked Conditions OR all linked Conditions have terminal status)
- [ ] **Finding:** Contradiction — active care plan with no active diagnoses
- [ ] **Evidence:** CarePlan ID, status, linked Condition IDs (if any) and their statuses
- [ ] **Test cases:** ≥2 cases

#### Rule 2: Completed CarePlan But Active Medications/Procedures
- [ ] **Trigger:** CarePlan.status = "completed" OR "cancelled" AND ≥1 linked Medication or Procedure has status = "active", "in-progress"
- [ ] **Finding:** Contradiction — plan concluded but treatments ongoing
- [ ] **Evidence:** CarePlan ID, status, active resource IDs and types
- [ ] **Test cases:** ≥2 cases (medication, procedure)

#### Rule 3: CarePlan Period Inconsistent with Status
- [ ] **Trigger:** CarePlan.period.end < current_date AND CarePlan.status = "active"
- [ ] **Finding:** Contradiction — active plan but period has expired
- [ ] **Evidence:** CarePlan ID, status, end date, current date
- [ ] **Test cases:** ≥2 cases (end date = today, yesterday)
