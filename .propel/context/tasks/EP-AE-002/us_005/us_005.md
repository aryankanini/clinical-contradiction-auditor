# US-AE-005: Condition Cross-Resource Contradiction Rules

## Story

As a data quality reviewer, I need to detect contradictions involving Condition resources so that diagnosis consistency issues are surfaced before clinical use.

## User Value

Conditions anchor the clinical narrative. When a condition is marked active but related resources (CarePlans, Medications, Encounters) are closed, decision-makers operate with incomplete or false information. This story implements the core contradiction detection for the most clinically critical resource type.

## Acceptance Criteria

### Condition Contradiction Rules
Each rule below is implemented as a deterministic Rule subclass per US-AE-001.

#### Rule 1: Active Condition with Closed Care Plan
- [ ] **Trigger:** Condition.status = "active" AND all linked CarePlans have status = "completed" or "cancelled"
- [ ] **Finding:** Contradiction — active diagnosis requires active care plan, but none exists
- [ ] **Evidence:** Condition ID, Condition status, linked CarePlan IDs and their statuses
- [ ] **Test cases:** ≥2 cases (true contradiction, false positive avoidance)

#### Rule 2: Condition with Past End Date But Active Encounter
- [ ] **Trigger:** Condition.abatementDateTime < current_date AND referenced in open Encounter (status ≠ finished, cancelled)
- [ ] **Finding:** Contradiction — condition resolved but still referenced in active encounter
- [ ] **Evidence:** Condition ID, abatement date, Encounter ID, Encounter status, current date
- [ ] **Test cases:** ≥2 cases (edge case: abatement = yesterday, today, future)

#### Rule 3: Terminal Condition Referenced in Ongoing Care
- [ ] **Trigger:** Condition.status = "resolved" OR "entered-in-error" AND linked to active Encounter, active Procedure, or active CarePlan (status ≠ completed, cancelled)
- [ ] **Finding:** Contradiction — concluded diagnosis still referenced in active care
- [ ] **Evidence:** Condition ID, Condition status, active resource IDs and types
- [ ] **Test cases:** ≥3 cases (each active resource type)

#### Rule 4: Condition References Inactive Medication
- [ ] **Trigger:** Condition.code implies a medication (e.g., "type 2 diabetes" implies antidiabetic meds) AND all linked Medications have status = "inactive" or end date ≤ current_date
- [ ] **Finding:** Contradiction — active condition but no active treatment medication
- [ ] **Evidence:** Condition ID, Condition code, linked Medication IDs, Medication statuses
- [ ] **Test cases:** ≥2 cases (strong implication, weak implication)

### Performance & Scale
- [ ] Rules execute in <100ms per patient record (including I/O and lookups)
- [ ] Rules handle patient cohorts of 1K–100K records without memory overflow
- [ ] Test: measure execution time on 10K patient sample

### Evidence Payload
- [ ] Every finding includes:
  - Condition resource ID
  - Condition status and relevant dates
  - IDs and statuses of conflicting resources
  - Rule-specific logic explanation (human-readable)
  - Exact field names and values that contradict
  
### Test Scenarios
- [ ] Test dataset includes:
  - ≥5 true contradiction cases (should be found)
  - ≥5 false positive cases (should NOT be found, e.g., resolved condition with no active references)
  - Edge cases: null dates, missing links, circular references
