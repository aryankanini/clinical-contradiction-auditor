# US-AE-006: Medication Cross-Resource Contradiction Rules

## Story

As a medication safety auditor, I need to detect contradictions involving Medication resources so that medication consistency issues do not propagate to care teams.

## User Value

Medications represent active clinical treatments. Contradictions involving medication status, indication, or linkage can lead to unsafe dosing, drug interactions, or discontinued treatments being unknowingly continued. This story implements critical medication-centered contradiction detection.

## Acceptance Criteria

### Medication Contradiction Rules
Each rule below is implemented as a deterministic Rule subclass per US-AE-001.

#### Rule 1: Active Medication Not Referenced in Any Active Care Plan
- [ ] **Trigger:** Medication.status = "active" OR (end_date > current_date) AND no active CarePlan references it
- [ ] **Finding:** Contradiction — medication prescribed but no active treatment plan documents its use
- [ ] **Evidence:** Medication ID, Medication status, end date, searched CarePlan IDs (if any)
- [ ] **Test cases:** ≥2 cases (truly orphaned, wrongly marked active)

#### Rule 2: Medication Status Conflicts with Related Encounter/Condition
- [ ] **Trigger:** Medication.status = "completed" OR "stopped" AND (referenced in active Encounter OR related Condition is active)
- [ ] **Finding:** Contradiction — medication discontinued but still in use
- [ ] **Evidence:** Medication ID, Medication status, active Encounter or Condition IDs
- [ ] **Test cases:** ≥2 cases (stop date = today vs. yesterday)

#### Rule 3: Medication Indication Mismatched with Condition
- [ ] **Trigger:** Medication.indication (code) is clinically inconsistent with linked Condition.code
  - Example: Antibiotic prescribed for non-infectious condition
  - Use lookup table: indication → expected condition codes
- [ ] **Finding:** Contradiction — medication indication doesn't support stated condition
- [ ] **Evidence:** Medication ID, indication code, Condition ID, condition code, lookup result
- [ ] **Test cases:** ≥2 cases (clear mismatch, edge case)

#### Rule 4: Medication End Date Conflicts with Future Reference
- [ ] **Trigger:** Medication.effective_end_date < current_date AND referenced in Encounter or CarePlan with start date > current_date
- [ ] **Finding:** Contradiction — medication expired but referenced in future care
- [ ] **Evidence:** Medication ID, end date, future Encounter/CarePlan IDs, their start dates
- [ ] **Test cases:** ≥2 cases (end date = today, yesterday)

#### Rule 5: Medication Dosage Status Conflicts with Medication Status
- [ ] **Trigger:** Medication has multiple dosages (e.g., morning and evening) AND overall Medication.status = "stopped" BUT some dosages have status = "active"
- [ ] **Finding:** Contradiction — medication marked stopped but individual doses still active
- [ ] **Evidence:** Medication ID, Medication status, dosage IDs and statuses
- [ ] **Test cases:** ≥2 cases (partial conflict, full conflict)

### Performance & Scale
