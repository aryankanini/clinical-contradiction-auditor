# User Story - US_004

## Story ID

- ID: US_004

## Story Title

- Normalize rule-critical FHIR fields

## Status

- **State**: Closed
- **Superseded By**: N/A
- **Change Request**: N/A

## Description

- As a platform engineer, I want deterministic normalization logic for rule-critical FHIR fields, so that contradiction detection receives comparable inputs across all staged resources.

## Business Value

- Enables accurate cross-resource checks by converting heterogeneous source values into rule-ready normalized fields.

## Acceptance Criteria

### AC-01: Normalize statuses consistently

- **Given**: Source resources contain status fields with family-specific representations
- **When**: The normalization pipeline processes the records
- **Then**: Status values are mapped into the canonical status model
- **And**: Unmappable values are flagged with deterministic normalization outcomes

### AC-02: Normalize timestamps and ordering fields

- **Given**: Source resources contain time-related fields needed for stale-state or sequence validation
- **When**: The normalization pipeline processes the records
- **Then**: Rule-critical timestamps are transformed into the canonical time representation
- **And**: Missing or ambiguous times are surfaced explicitly rather than hidden

### AC-03: Normalize reference linkages

- **Given**: Source resources contain cross-resource references used by contradiction rules
- **When**: The normalization pipeline processes the records
- **Then**: References are resolved into canonical linkage fields where possible
- **And**: Unresolved references are marked for completeness handling

## Edge Cases

- Conflicting timestamp fields on one resource
- References pointing to records missing from the current batch
- Multiple statuses where one source resource exposes both lifecycle and workflow state
