# US-AE-002: Rule Pack Versioning & Validation

## Story

As a compliance auditor, I need to confirm that the rule version used in a batch audit is known and immutable so that findings are traceable to the exact rule logic that generated them.

## User Value

Rule pack versioning enables reproducibility and audit defensibility. If findings change between audits on the same data, we can trace the change to a specific rule modification and justify the update to stakeholders.

## Acceptance Criteria

### Rule Pack Metadata
- [ ] Rule pack includes version metadata:
  - `version` (semver: major.minor.patch)
  - `release_date` (ISO 8601 date)
  - `change_log` (text summary of changes from previous version)
  - `active_status` (true = current; false = archived)
  
### Version Persistence with Batch Audits
- [ ] Batch audit run captures and stores:
  - `batch_run_id` (UUID, unique per audit run)
  - `rule_pack_version` (e.g., "2.1.0")
  - `audit_timestamp` (ISO 8601, execution start time)
  - Audit metadata is immutable after batch completion
  
### Rule Pack Validation
- [ ] Validator checks rule pack syntax:
  - All rules present and instantiable (no missing classes, no import errors)
  - No circular rule dependencies (Rule A depends on Rule B depends on Rule A)
  - All rules include valid metadata (delegate to US-AE-001 validation)
  - No duplicate rule_ids across versions (historical check)
  
### Safety Tag Validation
- [ ] Validator rejects any rule that:
  - Is missing `["deterministic", "audit_only", "no_side_effects"]` tags
  - Contains code that modifies input resources
  - Contains code that emits diagnostic or clinical claims (heuristic: scan for keywords like "diagnose", "prescribe", "treat", "alter_intent")
  - Contains non-deterministic constructs (random, datetime.now, uuid, external API calls)
  
### Version History & Retrieval
- [ ] System can query rule version history:
  - `get_rule_version(rule_pack_version)` → returns rule pack object
  - `get_findings_for_version(rule_pack_version)` → returns all findings from batches using that version
  - `list_rule_versions()` → returns all versions with release dates
  
### Rule Pack Immutability
- [ ] After a rule pack version is released:
  - Version is archived and read-only (no modification)
  - New changes create a new version (major/minor/patch bumped)
  - Rollback to previous version is allowed (reactivate archived version)
  - Audit log records every version activation/deactivation
  
### Versioning Scenarios
- [ ] Test cases:
  - Release v1.0.0, run audit batch A, confirm audit metadata = "1.0.0"
  - Release v1.1.0 (patch fix for rule X), run audit batch B, confirm batch uses "1.1.0"
  - Load both versions, run same data through each, confirm findings differ (v1.1.0 catches more/different contradictions due to fix)
  - Attempt to modify v1.0.0 rules, confirm rejection (immutable)
  - Query findings by version, confirm v1.0.0 findings != v1.1.0 findings on same cohort

## Unit Tests
- [ ] Test suite covers:
  - Valid version string formats (rejects "2.0", "v2.0.1", "2.0.0.0", accepts "2.0.0", "2.1.3")
  - Metadata completeness (rejects missing version, release_date, change_log)
  - Circular dependency detection (Rule A → B → A)
  - Safety tag validation (rejects missing required tags)
  - Non-deterministic code detection (heuristic scan for random, datetime.now, etc.)
  - Immutability enforcement (write-protect archived versions)
  - Version history retrieval (correct version returned for batch_run_id)

## Definition of Done

- [ ] Rule pack schema updated to include version metadata and active_status flag
- [ ] Batch audit metadata captures rule_pack_version (passed through audit pipeline)
- [ ] Rule pack validator in `module_2_audit_engine/deterministic/rule_validator.py` covering syntax, safety, determinism
- [ ] Rule pack archive in `data/rule_packs/` with versioned directories (v1.0.0/, v1.1.0/, etc.)
- [ ] Query functions: `get_rule_version()`, `get_findings_for_version()`, `list_rule_versions()` in rule registry
- [ ] Unit tests in `tests/unit/test_rule_versioning.py` (all AC test cases)
- [ ] Integration test: load v1.0, audit batch X, load v1.1, audit same batch, compare findings
- [ ] Documentation: rule pack YAML schema, versioning policy, immutability guarantees

## Technical Notes

- Use semantic versioning (semver) library for version parsing and comparison
- Archive rule packs with version in path: `rule_packs/v2.1.0/rules.yaml`
- Store audit metadata in database or audit log (persistent)
- Safety scan: use AST parsing or regex heuristics to detect non-deterministic patterns
- Consider using immutable file system (read-only after archive) or database row-level permissions
