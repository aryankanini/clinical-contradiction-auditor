# US-AE-001: Rule Interface Contract & Loader

## Story

As a deterministic rule engine developer, I need to define and implement a rule interface contract and loader so that all contradiction detection rules follow a consistent, auditable contract.

## User Value

Deterministic rule execution is the authoritative source for contradiction detection. A consistent interface ensures every rule produces immutable, reproducible outputs that can be safely logged and traced for audit purposes.

## Acceptance Criteria

### Core Interface Contract
- [ ] **Rule ABC (Abstract Base Class)**
  - Defines abstract method: `execute(normalized_resources: Dict[str, List[dict]]) -> List[Finding]`
  - Signature is immutable (type hints, docstring, parameter defaults all fixed)
  - Prevents rules from modifying input resources (ideally via read-only wrappers or @property decorators)
  
### Rule Metadata
- [ ] Every rule includes mandatory metadata:
  - `rule_id` (string, unique within rule pack)
  - `version` (semver format: major.minor.patch)
  - `description` (human-readable summary)
  - `resource_types_in_scope` (list of FHIR resource types the rule evaluates)
  - `safety_tags` (list: ["deterministic", "audit_only", "no_side_effects", "immutable_output"])
  - Metadata is immutable after rule instantiation
  
### Rule Loader
- [ ] Loader reads YAML rule pack from disk or stream
- [ ] Deserializes YAML into rule object instances (one per rule definition)
- [ ] Validates each rule:
  - All mandatory metadata fields present and non-empty
  - `rule_id` is unique within the pack
  - `version` matches semver pattern
  - `resource_types_in_scope` lists valid FHIR types (Condition, Medication, Procedure, Encounter, Observation, CarePlan)
  - `safety_tags` includes required tags
- [ ] Raises `RulePackValidationError` with clear error messages if validation fails
  - Example: "Duplicate rule_id 'condition_active_plan_closed' in rule pack v2.0"
  - Example: "Rule 'med_conflict' missing mandatory metadata field: resource_types_in_scope"
  
### Deterministic Guarantee
- [ ] Rule execution is deterministic:
  - Same input (normalized resources) produces identical output (same findings, same order) every time
  - No randomness, no timestamp variation, no state mutations
  - Test: Execute same rule on identical resources 5 times, verify bit-for-bit identical findings
  
### Error Handling
- [ ] Rule loader gracefully handles:
  - Missing YAML file (raises FileNotFoundError)
  - Malformed YAML syntax (raises YAMLParseError)
  - Invalid rule type in pack (raises ClassNotFoundError)
  - Missing ABC implementation (raises TypeError: "Rule must inherit from RuleInterface")
  
### Unit Tests
- [ ] Test suite covers:
  - Valid rule pack loads successfully
  - Invalid pack (missing field) raises ValidationError with specific field name
  - Duplicate rule IDs detected and reported
  - Semver validation (rejects "2.0", "v2.0.1", "2.0.0.0", accepts "2.0.0")
  - Resource type validation (accepts valid types, rejects typos)
  - Safety tag validation (requires at least ["deterministic", "audit_only"])
  - Rule execution determinism (3 runs, identical outputs)
  - No input resource mutation (verify original unmodified after rule execution)

## Definition of Done

- [ ] Rule ABC interface implemented in `module_2_audit_engine/deterministic/rule_interface.py`
- [ ] Rule loader implemented in `module_2_audit_engine/deterministic/rule_loader.py`
- [ ] Unit tests in `tests/unit/test_rule_interface.py` (all AC test cases)
- [ ] Rule pack schema documented (YAML structure, metadata fields, validation rules)
- [ ] Sample valid and invalid rule packs provided for testing
- [ ] Code passes linting and type checking
- [ ] Documentation: docstrings on RuleInterface, Loader, metadata fields
- [ ] Integration test: load sample rule pack, instantiate all rules, verify metadata

## Effort Estimate

**5 person-days** (M-sized task)

## Dependencies

- None (foundational)

## Technical Notes

- Use Python ABC and @abstractmethod for rule interface
- Rule loader: PyYAML for parsing, pydantic or dataclass for validation
- Immutability: use `dataclass(frozen=True)` for Finding objects or implement `__setattr__` guards
- Consider using a factory pattern for rule instantiation from YAML class references
