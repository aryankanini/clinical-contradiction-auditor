# US-AE-011: Severity Scoring Algorithm & Tier Assignment

## Story

As a triage coordinator, I need findings automatically assigned a severity tier so that operations can prioritize high-impact issues.

## User Value

Without severity triage, operators can't distinguish between a minor documentation inconsistency and a medication safety contradiction affecting active treatment. Automatic, deterministic severity scoring enables effective resource allocation and SLA-driven escalation.

## Acceptance Criteria

### Severity Tier Definitions

#### CRITICAL
- [ ] **Criteria (any one triggers CRITICAL):**
  - Multi-resource contradictions involving active medications (active status AND no end_date)
  - Active Medication referenced in contradiction with Encounter or CarePlan
  - Active Condition contradicted with closed/inactive CarePlan (diagnosis needs treatment)
  - Violation of regulatory requirement (e.g., HIPAA data completeness, medication reconciliation rule)
  - Procedure status contradiction with active Encounter (care incomplete or conflicting)
  
- [ ] **Test cases:** ≥3 CRITICAL scenarios

#### HIGH
- [ ] **Criteria (any one triggers HIGH):**
  - Contradictions affecting ≥3 resources (multi-resource involvement)
  - Historical Condition or Medication status conflicts
  - Stale state where last_update > 180 days (older stale)
  - State lifecycle violation (impossible transition)
  - Temporal ordering violation (events inverted)
  
- [ ] **Test cases:** ≥3 HIGH scenarios

#### MEDIUM
- [ ] **Criteria (any one triggers MEDIUM):**
  - Single-resource state issues (e.g., resource with inverted date range)
  - Stale state where 90 ≤ last_update_days ≤ 180 (normal stale)
  - Observation or non-critical resource status contradictions
  - Minor temporal violations (documentation field out of sequence)
  
- [ ] **Test cases:** ≥3 MEDIUM scenarios

#### LOW
- [ ] **Criteria (any one triggers LOW):**
  - Deprecated or archived resource contradictions
  - Documentation-only field inconsistencies
  - Informational contradictions (e.g., observation comment vs. result)
  - Non-blocking resource state issues
  
- [ ] **Test cases:** ≥2 LOW scenarios

### Severity Scoring Algorithm
- [ ] Algorithm factors:
  - **Rule Weight:** 1–5 (defined in rule YAML; 5 = high-impact rule)
  - **Resource Impact:** count of affected resources (1 = 0 points, 2–3 = 1 point, 4+ = 2 points)
  - **Business Outcome:** 0–3 points (affects active care, compliance, reporting)
  - **Total Score:** rule_weight + resource_impact + business_outcome
  
- [ ] Scoring thresholds:
  - Score ≥10 → CRITICAL
  - 7–9 → HIGH
  - 4–6 → MEDIUM
  - <4 → LOW
  
- [ ] Scoring is deterministic:
  - Same rule + resources → same score every time
  - Test: score same contradiction 5 times, verify identical

### Scoring Documentation
- [ ] Algorithm is documented:
  - Decision tree or scoring formula
  - Rule weight assignments (example: medication contradictions = 5, documentation = 1)
  - Business outcome scoring rubric
  - Examples: "medication safety finding scores 10 (weight 5 + resources 2 + outcome 3) = CRITICAL"

### Severity Assignment
- [ ] Every finding receives a severity tier:
  - Assigned during finding hydration (EP-AE-004 step)
  - Stored in Finding.severity_tier field
  - At least 80% of findings assigned non-LOW tier (quality gate)

### Test Scenarios
- [ ] Test with 30 diverse findings:
  - Verify tier assignments match expected severity
  - Verify determinism: same finding scored consistently
  - Verify ≥80% non-LOW assignment (coverage check)
  
## Unit Tests
- [ ] Severity scoring algorithm:
  - Score calculation correct per formula
  - Boundary testing (score = 10, 9, 7, 6, 4, 3, 0)
  - Determinism: same input → same score 5 times
  - Rule weights apply correctly
  
- [ ] Tier assignment:
  - Score → tier mapping correct
  - All findings assigned tier (no nulls)

## Integration Tests
- [ ] Score 50 diverse findings from different rule types
- [ ] Verify 80%+ assigned non-LOW tier
- [ ] Verify distribution is sensible (some CRITICAL, some MEDIUM, etc.)
- [ ] Verify determinism across multiple scoring runs
