# User Story - US_007

## Story ID

- ID: US_007

## Story Title

- Persist ingest provenance metadata

## Status

- **State**: Closed
- **Superseded By**: N/A
- **Change Request**: N/A

## Description

- As a compliance reviewer, I want ingestion runs to persist provenance metadata, so that downstream findings can be traced back to source batches and processing outcomes.

## Business Value

- Provides the minimum audit trail needed to reproduce and defend downstream contradiction findings.

## Acceptance Criteria

### AC-01: Record ingest-run provenance

- **Given**: A batch has completed intake and staging
- **When**: Ingest-run metadata is persisted
- **Then**: The record includes source batch identity, processing status, and family-level or record-level counts
- **And**: The metadata is stable enough to reference from downstream findings

### AC-02: Record normalization and validation outcomes

- **Given**: A batch contains a mix of successful, partial, and failed ingest outcomes
- **When**: Ingest provenance is persisted
- **Then**: The stored metadata captures normalization and linkage-validation outcomes
- **And**: Partial-processing states are distinguishable from full success or full failure

### AC-03: Preserve immutable provenance facts

- **Given**: An ingest run has been recorded
- **When**: Downstream systems reference the provenance artifacts
- **Then**: The provenance fields represent immutable facts about the ingest process
- **And**: They are not overwritten by later explanation or resolution workflows

## Edge Cases

- Reprocessing the same batch with a newer rule-pack version later in the pipeline
- Partial retry of records from a previously failed batch
- Source system identifiers that are non-unique without extra provenance fields
