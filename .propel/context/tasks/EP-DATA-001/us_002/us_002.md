# User Story - US_002

## Story ID

- ID: US_002

## Story Title

- Implement FHIR resource family loaders

## Status

- **State**: Closed
- **Superseded By**: N/A
- **Change Request**: N/A

## Description

- As a platform engineer, I want loaders for each in-scope FHIR resource family, so that accepted batches can be staged into a consistent ingestion pipeline.

## Business Value

- Converts the intake contract into executable loading behavior and creates the first working vertical slice of the ingestion layer.

## Acceptance Criteria

### AC-01: Load all supported resource families

- **Given**: A valid batch contains records for one or more in-scope FHIR resource families
- **When**: The ingestion layer executes the resource loaders
- **Then**: Each supported resource family is routed to its corresponding loader
- **And**: The staged output preserves source record identifiers and resource type labels

### AC-02: Support partial family presence

- **Given**: A valid batch contains only a subset of the six in-scope resource families
- **When**: The ingestion layer executes the resource loaders
- **Then**: Present families are loaded successfully
- **And**: Missing families are recorded as absent rather than treated as parser failures

### AC-03: Capture loader-level failure status

- **Given**: One resource-family loader encounters a deterministic parsing failure for a record
- **When**: The ingestion layer processes the batch
- **Then**: The affected record is marked with a loader failure outcome
- **And**: The ingest-run metadata reflects both successful and failed record counts

## Edge Cases

- Unknown extensions inside otherwise supported FHIR resources
- Repeated resource identifiers across families
- Batches that exceed the expected family count for one patient cohort
